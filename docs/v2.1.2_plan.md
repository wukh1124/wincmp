# WinCMP v2.1.2 規格審查與實作規劃 (Technical Spec & Roadmap)

本文件定義 WinCMP v2.1.2 的四大核心改進規格、技術架構與實作任務。

---

## 1. 側邊欄收合機制簡化 (UI/UX)

### 1.1 規格與變更
- **移除鎖定狀態**：徹底移除頂部 `#btn-lock-sidebar` 按鈕與 `isSidebarLocked` 狀態。
- **取消自動收合**：切換頁籤（包含專案管理）不再自動收合，維持使用者當前狀態。
- **狀態持久化**：保留 `#btn-toggle-sidebar`，收合狀態儲存於 `localStorage`（鍵名：`wincmp_sidebar_collapsed`），應用重載後維持。
- **清理廢棄字典**：移除 `i18n` 中「解鎖側邊欄自動收合」與「鎖定側邊欄自動收合」。

### 1.2 UI 佈局 (ASCII)

```text
+-------------------------------+
| [Logo] WinCMP            [◀]  |  <-- 僅保留極簡折疊按鈕 (狀態持久化)
+-------------------------------+
| 頁面切換一律保持原狀，不再強制收合
```

## 2. PHP Redis 擴充支援與配置平滑遷移

### 2.1 規格與變更
- **平滑遷移 (`EnsurePHPIniRedisExtension`)**：
  - 於 `internal/config/init.go` 啟動流程中檢測 `conf/php/php.ini`。
  - 若缺少 `extension=redis`：自動備份為 `php.ini.bak`，並安全追加 `extension=redis`。
  - 若存在 `;extension=redis`（被註解）：自動取消註解。
- **PHP 卡片擴充狀態徽章 (Badge)**：
  - 儀表板 (`Dashboard.tsx`) PHP FastCGI 卡片新增 Redis 狀態徽章：
    - `[⚡ Redis: 已啟用]`（綠色）：DLL 存在且 ini 已啟用。
    - `[⚠️ Redis: 未在 php.ini 啟用]`（黃色）：DLL 存在但 ini 缺少，點擊一鍵啟用。
    - `[Redis: 未安裝 DLL]`（灰色）：缺少 DLL，點擊引導至依賴管理。
- **依賴管理假陽性校正**：
  - 修正 `DependencyManager.tsx`，只有在 DLL 存在且 `php.ini` 有效啟用時才顯示「已就緒」。

### 2.2 UI 佈局 (ASCII)

```text
+-------------------------------------------------------------+
| [Server] PHP 8.2.30                            [● 運行中]   |
| 埠口: 38200 ~ 38202   擴充: [⚡ Redis: 已啟用]              | <-- 新增狀態徽章
+-------------------------------------------------------------+
```

## 3. 內建 Redis 簡易瀏覽器 (DBExplorer 擴充)

### 3.1 規格與技術架構
- **架構方案**：自研內建於 `DBExplorer`，後端引入官方 `github.com/redis/go-redis/v9`，直接連線本機 Redis (`127.0.0.1:6379`)。
- **介面佈局**：頂部增加分頁切換 `[ 🗄️ MariaDB ]` 與 `[ ⚡ Redis ]`。
- **核心功能**：
  1. **DB 切換**：支援 DB 0 ~ DB 15 切換，顯示各 DB 鍵值數量 (`DBSIZE`)。
  2. **安全分頁搜尋**：使用 `SCAN` 指令分頁遍歷（嚴禁使用阻塞性 `KEYS *`），支援 Pattern 匹配搜尋。
  3. **鍵值檢視**：
     - 顯示 Key 名稱、資料型態（string, hash, list, set, zset）、TTL 倒數秒數。
     - 支援 JSON 格式化與純文字檢視。
  4. **快取操作**：
     - 單鍵刪除 (`DEL key`)。
     - 清空當前 DB (`FLUSHDB`，帶 `customConfirm` 二次確認彈窗)。
  5. **未啟動防護**：Redis 未運行時顯示友善引導卡片，可一鍵前往儀表板啟動。

### 3.2 UI 佈局 (ASCII)

```text
+-------------------------------------------------------------------------+
| [ 🗄️ MariaDB ]  [ ⚡ Redis ]                                            |
+-------------------------------------------------------------------------+
| 連線: 127.0.0.1:6379 (運行中)  | DB: [ DB 0 (42 keys) ▼ ]  [ 重新整理 ]  |
| 鍵名搜尋: [ laravel_cache:*          ]  [ 清空快取 (FLUSHDB) ]          |
+------------------------------------+------------------------------------+
| 鍵名 (Key)              | 型態     | 詳細資料 (Key Detail)              |
|-------------------------+----------| 名稱: laravel_cache:session_abc123 |
| > session_abc123        | string   | 類型: STRING   TTL: 7198s          |
| > tag:users:values      | hash     | 值內容:                            |
|                         |          | { "user_id": 42, "role": "admin" } |
|                         |          | [ 刪除此鍵 (DEL) ]                 |
+------------------------------------+------------------------------------+
```

## 4. Runtime 指令防護與 Port 釋放保證

### 4.1 規格與變更
- **自訂指令安全攔截**：
  - 於 `internal/process/runtime.go` 攔截以 `start `（不分大小寫）開頭之指令。
  - 避免 Windows `cmd.exe /c start` 產生脫鉤進程破壞 Job Object 監控體系，提示使用者改用原生前台指令。
- **Port 釋放保證 (後端同步輪詢)**：
  - 改進 `KillProcessByPort(port)`：在呼叫 `taskkill /F /T` 後，後端主動輪詢 TCP 狀態（每 150ms 檢查一次，最多 3 秒），確認端口完全釋放後才回傳。
  - 徹底解決 Windows TCP Socket `TIME_WAIT` 時差導致的 `EADDRINUSE` 崩潰或 Vite 自動跳號至 3001 問題。
- **啟動前置防護**：
  - 後端 `StartRuntime` 前置校驗 Port，若仍被佔用則直接報錯，防止雙重綁定或異常行為。

## 5. 影響評估 (Impact Analysis)

| 模組 | 影響範圍 | 風險等級 | 評估與相容性說明 |
| :--- | :--- | :--- | :--- |
| **側邊欄收合** | 前端 `App.tsx` | 極低 | 僅影響側邊欄 UI 狀態，完全向後相容。 |
| **PHP Redis 配置** | `conf/php/php.ini` | 低 | 啟動時自動備份 `.bak`，僅補齊 `extension=redis`，不覆蓋使用者自訂設定。 |
| **Redis 瀏覽器** | 後端 Go / 前端 `DBExplorer` | 低 | 新增模組與相依套件 (`go-redis/v9`)，獨立運行，不干擾 MariaDB 既有邏輯。 |
| **Port 釋放與防護** | `internal/process/runtime.go` | 低 | 強化終止可靠度，消除 `EADDRINUSE` 競態條件，大幅提升專案重啟成功率。 |
