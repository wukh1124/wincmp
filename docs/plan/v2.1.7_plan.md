# v2.1.7 更新計畫

主題：**PHP2Shell（CVE-2026-109618 / CVE-2026-109619）安全應變**。本版以「讓使用者能立即取得已修補的 PHP 執行環境」為第一優先，其餘項目僅收低風險、同主題的收尾與修正。

## 1. PHP 安全修補與依賴版本 (PHP Security Patch & Dependency Versions)

- [x] **PHP 小版本安全更新**：
  - `php82` 8.2.33 → **8.2.35**、`php83` 8.3.33 → **8.3.36**、`php84` 8.4.25 → **8.4.27**。
  - 上游於 2026-10-21 發布，修補 CVE-2026-109618（OOM 記憶體毀損導致 RCE）與 CVE-2026-109619（stale global state 導致 RCE），CVSS v4.0 皆為 9.2。
  - SHA-256 逐項與官方 `sha256sum.txt` 交叉核對通過。
- [x] **新增 PHP 8.5 支援**：
  - `conf/dependencies.json` 新增 `php85`（8.5.12，`php-8.5.12-nts-Win32-vs17-x64.zip`）與 `php_redis_85`（PECL redis 6.3.0，8.5 NTS VS17 版本）。
  - 前端依賴清單與掃描器皆為通用邏輯（`php` 前綴 + `php_redis_<suffix>`），無需額外硬編碼。
- [x] **php_redis 版本後綴改為通用推導**：
  - `downloader_bridge.go` 原本以 `_82/_83/_84/_73/_74` 硬編碼白名單比對，新增 `_85` 時會得到空字串，導致 8.5 的 DLL 被複製進所有 PHP 目錄（ABI 不符）。
  - 改為由 key 後綴推導「主.次」版本，並在辨識失敗時明確跳過搬移。
- [x] **PHP 下載來源改為直連**：
  - `windows.php.net` 現以 302 轉址至 `downloads.php.net`；四個 PHP 下載網址改為直連，避免多一次重導，也讓網域白名單校驗的落點與 URL 一致。
- [x] **其他依賴版本更新（P1）**：
  - Caddy 2.11.4 → **2.11.7**、Node.js 24.21.0 → **24.22.1**（上游標記為 security release）、MariaDB 11.4.10 → **11.4.13**、Mailpit 1.31.1 → **1.31.6**。
  - Composer 2.10.3、HeidiSQL 12.21、Redis 5.0.14.1 已是上游最新，不動。
  - SHA-256 取得方式：Node 對官方 `SHASUMS256.txt`、MariaDB 對官方 REST API checksum、Mailpit 對 GitHub Release asset digest；Caddy 上游 `checksums.txt` 僅提供 SHA-512，故以官方 release asset 實際下載計算後填入。
- [x] **PHP archives 備援改為網域通用**：
  - 上游 commit `52e99a0` 新增「`releases/` 遇 404 自動改用 `releases/archives/`」備援，但判定寫死 `windows.php.net`；本次 PHP 連結改直連 `downloads.php.net` 後會失去該備援。
  - 改以 `php.net` 網域後綴判斷（新增 `archivesFallbackURL()`），`internal/downloader/downloader.go` 與 `scripts/check_deps.go` 同步，兩者行為一致。
- [x] **cacert 改用不可變日期快照**：
  - 現行指向滾動的 `cacert.pem`，Mozilla 一更新憑證庫，釘住的 SHA-256 立刻失效並讓下載校驗失敗（使用者會看到「完整性校驗失敗」）。
  - 已改為 `cacert-2026-10-20.pem`（118 張憑證，不可變），`version` 欄位同步為 `2026-10-20`，SHA-256 與 `cacert-2026-10-20.pem.sha256` 官方值相符。
  - 下載後仍存為 `conf/ssl/cacert.pem`，檔名與既有 PHP 啟動參數不受影響。
- [x] **文件與範例版本同步**：
  - `packaging/wincmp/readme.md`、`readme_zh.md` 的資料夾範例更新為 `php-8.5.12`。
  - 根目錄 `readme.md` / `readme_zh.md` 的 Port 基數說明補上 `PHP 8.5 → 38500+`。
  - `docs/How to use caddy.md` 的 FastCGI 路徑範例更新為 `php-8.5.12`。
  - 另修正既有文件錯誤：PHP 官方 zip 為扁平結構（無外層資料夾），實際路徑是 `bin/php/php-<版本>/`，原文寫成 `php-<版本>-nts-Win32-vsNN-x64/`；已於 `docs/dependencies.md` 更正並補上 archives 歸檔說明。

## 2. PHP 生命週期與風險可視化 (PHP Lifecycle & Risk Visibility)

動機：本次 CVE 對 7.3／7.4 沒有任何官方 Windows 二進位修補，但 WinCMP 仍可一鍵下載並啟動它們；使用者目前看不到任何風險提示。

- [ ] **EOL／無修補版本標示**：
  - 依賴庫管理與服務清單對 PHP 7.3、7.4 顯示「已停止支援（EOL）」徽章，8.2 顯示「2026-12-31 停止支援」預警。
  - 資料來源固定在後端一份版本生命週期表，避免散落在前端。
- [ ] **風險說明 tooltip**：
  - 說明「上游已不再提供 Windows 修補二進位，建議升級至 8.3 以上」，並提供跳轉至對應 PHP 分支下載的入口。
- [ ] **（可選）啟動時記錄一次性警告**：
  - 啟動 PHP 7.x 於 Runtime Log 記一筆提示（不阻斷啟動），讓使用者在日誌中也能看到。
- 需同步 `internal/i18n/i18n.go` 與 `frontend/src/i18n.ts` 雙語字典。

## 3. 掃描與版本比較正確性 (Scanner Accuracy)

- [x] **PHP 同分支版本比較修正**：
  - `internal/scanner/scanner.go:231` 以字串比較 `version > existing.Version`，會把 `8.4.9` 判定為比 `8.4.10` 新（字元 `9` > `1`）；同分支同時存在兩個 patch 目錄時可能選到較舊的執行檔。
  - 已改用同檔既有的 `compareVersions()`（`scanner.go:482`，數值分段比較），上／下兩個分支判斷都改。
- [x] **PHPList 排序統一**：
  - `scanner.go:276` 的版本排序同樣是字串比較，已一併改為 `compareVersions`，避免清單順序在跨 10 的 patch 上錯位。
- [x] **回歸測試**：
  - 新增 `internal/scanner/scanner_test.go`：`8.4.9` / `8.4.10` 並存時須保留 `8.4.10` 並把舊版記入 `SkippedPHP`，另含 `compareVersions` 邊界案例。

## 4. 舊版執行環境清理 (Stale Runtime Cleanup)

動機：本版開始會頻繁推 patch 版本，使用者的 `bin/php/` 會同時存在 `php-8.4.25` 與 `php-8.4.27`；掃描器只保留較新者，舊目錄被靜默忽略、持續佔用磁碟。

- [ ] **曝露 `SkippedPHP`**：
  - 後端 `ScanResult.SkippedPHP` 已有資料，但前端從未使用（僅存在於自動產生的 `models.ts`）。
  - 於依賴庫管理顯示「偵測到同分支舊版：8.4.25」提示。
- [ ] **一鍵清理舊 patch 目錄**：
  - 僅在同分支已有較新版本存在時提供；刪除前列出完整路徑並要求二次確認（`customConfirm`）。
  - 不動 `bin/php` 以外的目錄，不做「自動刪除」。

## 5. 發行與交付 (Release & Rollout)

- [ ] **推送順序（關鍵）**：
  - `DefaultDependencyURL` 指向 `raw.githubusercontent.com/wukh1124/wincmp/main/conf/dependencies.json`，而 `FetchRemoteDependencies` 以遠端覆蓋本地。
  - **必須先將 `conf/dependencies.json` 推上 `main` 再發版**，否則新版安裝的使用者按下「獲取最新」會被拉回含漏洞的舊版本。
- [ ] **舊安裝的生效路徑**：
  - 本地 `conf/dependencies.json` 已存在時不會被內嵌預設覆寫，既有使用者需按「獲取最新」或重裝；此點必須寫入 release notes。
- [ ] **發行文件**：
  - `release_note/v2.1.7/release_notes.md`、`release_notes_zh.md`（含日期行）、`audit_commits.md`。
  - 分類以 `### Security` 與 `### Dependencies` 為主，沿用 v2.1.1「預設依賴版本更新」的既有文風。
- [ ] **發行前驗證**：
  - `go test ./...`、`cd frontend && npm run build`、`go run scripts/check_deps.go --check --fast`（CI `release.yml` 目前用 `--check --fast`）。
  - 實機驗證：安裝 8.5.12 後 `bin/php/php-8.5.12/ext/php_redis.dll` 就位，且 8.2／8.3／8.4 的 `ext` 未被寫入 8.5 的 DLL。
